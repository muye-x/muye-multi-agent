01

架构原则

SDK 将 Agent 实现、HTTP transport 和公网边界分离。Agent 只产出 typed event 与统一结果；create_app() 负责 internal/public 协议；Nginx Gateway 只暴露 allowlist 内的 public 路由。

边界优先

不要将 /invoke、/capabilities 或 Order 服务加入公网 Nginx 路由。Public profile 仅投影可展示 Markdown、图表和 JSON。

02

五分钟创建一个 Agent

确定性逻辑使用 CustomAgent。实现 metadata 与 execute 后，由 SDK 统一管理超时、取消、session 锁与 HTTP 契约。

from muye_multi_agent_sdk import AgentMetadata, AgentRequest, AgentResult, CustomAgent, create_app

class EchoAgent(CustomAgent):
    @property
    def metadata(self) -> AgentMetadata:
        return AgentMetadata(name="echo", version="3.0.0", description="示例服务")

    async def execute(self, request: AgentRequest, **_) -> AgentResult:
        return AgentResult.success({"markdown": f"已处理：{request.task}"})

app = create_app(EchoAgent())

启动后使用 /health 检查进程，使用 /capabilities 协商协议版本、profile、意图和工具。

03

按工作流选择模式

模式适用场景实现职责
CustomAgent确定性流程、适配外部系统实现 execute()；可选 stream_events()
GraphAgent显式状态图、节点进度实现 build_graph() 与 result_from_state()
ReActAgent模型自主选择工具声明 instructions 与受限的 LangChain tools

工具的网络能力必须固定在注册表中，不接收模型提供的任意 URL。主 Agent 调用子 Agent 前读取 capabilities，确认 internal v3 协议与流式能力。

04

模型、协议与运行时

优先向 ReActAgent 注入已创建的模型实例；未注入时 SDK 根据 MUYE_SDK_MODEL_* 构建 provider。provider=muye 使用 muye-llm 的模型 alias，Thinking 开关留空时由网关默认配置决定；openai_compatible 适用于符合 OpenAI Chat Completions 规范的服务。

MUYE_SDK_MODEL_PROVIDER=muye
MUYE_SDK_MODEL_BASE_URL=http://127.0.0.1:9850
MUYE_SDK_MODEL=deepseek-v4-flash
MUYE_SDK_MODEL_ENABLE_THINKING=
MUYE_SDK_API_PROFILES=internal,public
MUYE_SDK_PUBLIC_PATH=/api/v1/example

Transport 统一提供 /health、/capabilities、/invoke、/invoke/stream 与 /cancel。流式请求的固定生命周期为 session_start → 中间事件 → done → session_end；调用子 Agent 前先读取 capabilities，再确认 internal v3、profile 和流式能力。

连接生命周期

SDK 创建的内置模型会在应用关闭时释放；调用方注入的 model 与 guard_model 由调用方管理，以便安全复用连接池。

05

短期上下文与意图守卫

短期上下文按 agent/profile/user_id/session_id 隔离。启用时调用方必须提供非默认 user_id 和 session_id，避免共享 checkpoint。

MUYE_SDK_INTENT_GUARD=true
MUYE_SDK_CONTEXT_PROFILES=internal,public
MUYE_SDK_CONTEXT_BACKEND=sqlite
MUYE_SDK_CONTEXT_SQLITE_PATH=./data/agent_checkpoints.db

ReAct 守卫只读取有限的人机文本历史，不读取系统提示、工具参数或工具结果。守卫澄清问题会写回同一 checkpoint，因此用户回复“西安”可以作为上一轮目的地追问的有效补充。守卫模型不可用时按 fail-open 处理，不应作为唯一安全边界。

06

部署与安全边界

  1. 配置服务：通过进程环境变量或本地未提交的 .env 注入配置，密钥只由部署环境提供。
  2. 启动依赖：先启动 muye-llm，再启动 agent-main、Travel 和 Order；使用 main.py --dry-run 验证入口。
  3. 收口公网：由 Gateway 配置 TLS、Bearer Token 和路由 allowlist；控制台只绑定 127.0.0.1。
  4. 保持 SSE：流式路由保留 proxy_buffering off、长读超时和断连取消语义。
不要提交运行时数据

API Key、Bearer Token、TLS 私钥、数据库 URI 与 SQLite checkpoint 均不得进入版本控制。

07

上线前验证清单

  • 所有服务 /health 返回成功，子 Agent 的 /capabilities 声明 internal v3。
  • public profile 不含 internal 的 origin_data、prompt_data 与领域异常详情。
  • 使用不同 user/session 验证短期上下文不会串会话；覆盖 SSE 的 done 与 session_end。
  • 执行 SDK、muye-llm、Dashboard API 回归测试与 main.py --dry-run。
