# v2.0 Migration Guide

v2.0 删除了固定 Travel/Order 服务、其端口、环境变量和公网路由。不要迁移旧业务源码；将可复用的领域知识转换为已确认的逻辑 Resource、Retrieval Skill 和 Agent Profile，再由 Generator 生成独立 Agent。

1. 为知识库建立 `config/knowledge/` 与 `config/approvals/` 中对应的受审计输入。
2. 使用 `knowledge analyze`、`approve-schema`、`approve-skill` 和 `agent approve-profile` 记录确认 checksum。
3. 执行 `agent generate <slug> --knowledge <knowledge-slug>`，再运行 `agent validate` 和生成目录自身测试。
4. 使用固定 digest 的基础镜像执行 `agent build`、`agent sync` 和 `agent deploy`。
5. 由管理员在 Control Web 中为用户授予 Agent；没有 grant 的用户不会在 Main 模型上下文中看到该工具。

已有目录一旦由开发者接管，Generator 不会覆盖。模板升级须运行 `agent diff <slug> --template latest`，人工审阅并合并差异；禁止通过复制历史 Travel/Order 目录规避 provenance、审批或构建记录。

迁移完成后应删除旧服务的 Compose 条目、DNS/防火墙规则与任何 `MUYE_AGENT_TRAVEL_*`、`MUYE_AGENT_ORDER_*` 配置。仅 Gateway 可暴露到公网。
