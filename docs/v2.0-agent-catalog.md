# Agent Catalog、权限与部署

- 状态：阶段 5 已实现
- 日期：2026-07-31
- 适用分支：Scaffold `v2.0.x-dev`

## 目标与边界

阶段 5 把生成 Agent 从源码目录接入可审计的运行链路：Descriptor 与 BuildRecord 确定性生成 Catalog/Compose，
Control 验证候选并等待 Main ACK，Main 按可信用户和最新 grant 生成请求级工具集合。固定 Travel/Order 示例仍为兼容
资产，但不再是 Main 的 SubAgent 发现来源。

调用拓扑固定为单向一层：

```text
trusted Gateway -> MainAgent -> authorized SubAgent -> muye-data -> published Resource
                         ^             ^                 ^
                         |             |                 |
                  Control Catalog   service token   Catalog identity
```

SubAgent descriptor 不能声明下游 Agent，Catalog entry 固定 `caller=agent-main`、`target_type=sub_agent`；反向或横向
调用不会进入 Main Registry。阶段 5 不提供 Web 管理、数据库 grant、registry manifest 发布或零停机切换，这些属于
阶段 6 或后续版本。

## 产物与事实源

| 路径 | 归属 | 规则 |
| --- | --- | --- |
| `agents/agent-<slug>/agent.yaml` | 开发者 | 身份、能力、Resource 和运行参数的唯一事实源 |
| `config/generated/builds/<agent_id>/<version>.json` | 构建流程 | 当前版本 BuildRecord 指针，可提交审阅 |
| `config/generated/builds/<agent_id>/records/*.json` | 构建流程 | 不可变历史 BuildRecord，供回滚使用 |
| `config/generated/agent-catalog.json` | `agent sync` | 确定性 Catalog，提交并由 CI `--check` 校验 |
| `compose.agents.generated.yaml` | `agent sync` | 可重建部署 aggregate，受 `.gitignore` 保护 |
| `config/generated/catalog-report.json` | `agent sync` | 可重建诊断报告，受 `.gitignore` 保护 |
| `config/runtime/control/` | Control | active Catalog、grant 和运行投影，不提交 Git |

`agent sync --check` 会在内存中完整生成并校验 Catalog、Compose 和 report，但只比较版本控制管理的
`agent-catalog.json`。因此全新 checkout 不要求预先存在两个可重建产物。

任一 descriptor、provenance、源码、BuildRecord、镜像摘要或全局唯一性检查失败时，整批 candidate 失败，旧产物不被
部分覆盖。启用部署的 Agent 还必须引用 `config/generated/resource-snapshot.json` 中已发布的 Resource；Snapshot 和
每个 Manifest checksum 都会重新计算。

## 配置与服务身份

Control 使用下列配置：

```text
MUYE_CONTROL_HOST=127.0.0.1
MUYE_CONTROL_PORT=9880
MUYE_CONTROL_STATE_ROOT=config/runtime/control
MUYE_CONTROL_GRANTS_PATH=config/runtime/control/user-agent-grants.json
MUYE_CONTROL_HEALTH_POLL_SECONDS=5
MUYE_CONTROL_HEALTH_FAILURE_THRESHOLD=3
MUYE_CONTROL_HEALTH_SUCCESS_THRESHOLD=2
MUYE_CONTROL_HEALTH_WINDOW_SECONDS=60
MUYE_CONTROL_OPERATOR_TOKEN=<deploy CLI only>
MUYE_CONTROL_MAIN_TOKEN=<Main only>
MUYE_CONTROL_HEALTH_TOKEN=<external health writer only>
MUYE_CONTROL_AGENT_TOKENS_JSON={"agent_product_handbook":"<Control probe token>"}
```

Main 使用 `MUYE_CONTROL_BASE_URL`、`MUYE_CONTROL_MAIN_TOKEN`、`MUYE_MAIN_CALLER_TOKEN`、
`MUYE_MAIN_AGENT_TOKENS_JSON` 和 Catalog/circuit breaker 参数。Data 生产环境使用
`MUYE_DATA_AGENT_AUTH_ENABLED=true`、`MUYE_DATA_AGENT_CATALOG_PATH`、`MUYE_DATA_AGENT_TOKENS_JSON`。

每个生成 Agent 的 Compose 服务要求部署环境提供：

```text
MUYE_AGENT_<NORMALIZED_AGENT_ID>_MAIN_TOKEN
MUYE_AGENT_<NORMALIZED_AGENT_ID>_CONTROL_TOKEN
MUYE_AGENT_<NORMALIZED_AGENT_ID>_DATA_TOKEN
```

例如 `agent_product_handbook` 对应前缀 `MUYE_AGENT_AGENT_PRODUCT_HANDBOOK_`。三个值必须非空且互不相同，生成
Agent 会在启动时拒绝缺失或复用；每类 JSON 映射也应为每个 Agent 分配独立随机值。对应关系为：

| Agent 容器变量 | 同值配置位置 | 权限 |
| --- | --- | --- |
| `MUYE_AGENT_MAIN_TOKEN` | Main 的 `MUYE_MAIN_AGENT_TOKENS_JSON[agent_id]` | invoke/stream/cancel/capabilities |
| `MUYE_AGENT_CONTROL_TOKEN` | Control 的 `MUYE_CONTROL_AGENT_TOKENS_JSON[agent_id]` | capabilities 健康采集 |
| `MUYE_AGENT_DATA_TOKEN` | Data 的 `MUYE_DATA_AGENT_TOKENS_JSON[agent_id]` | 仅 descriptor 绑定的 Resource |

Control 自身 operator/main/health token 也必须互不相同。token 只从 secret 环境注入，不写入 Catalog、Compose 实值、
BuildRecord、日志或命令输出。

## Grant 与请求级工具投影

阶段 5 的本地 grant store 是严格 JSON 文件，阶段 6 可替换为数据库实现：

```json
{
  "schema_version": "muye.ai/user-agent-grants/v1",
  "grants": [
    {"user_id": "user-001", "agent_id": "agent_product_handbook"}
  ]
}
```

Gateway 必须用 `MUYE_MAIN_CALLER_TOKEN` 认证并写入可信 `X-Muye-User-Id`。启用 Control 后，Main 不接受请求 body
中的 `user_id` 覆盖该身份。每次请求按以下交集投影工具：

```text
Main 当前有效 Catalog ACTIVE agent_id
INTERSECT Control 最新 user grant
EQUALS 本次请求可进入模型上下文的 SubAgent 工具
```

Control/grant 不可用时，本次请求降为零 SubAgent，而不是复用其他用户授权。网络调用前工具还会再次核对请求捕获的
Catalog revision 和 `allowed_agent_ids`。授权缓存只按 Catalog checksum 与完整授权集合复用 graph，不按用户扩大权限。

SubAgent 返回的可信 citation evidence 由 Main 绑定原用户、Agent 版本和请求 Catalog 后写回 Control；读取时再次检查
当前 grant 与 active Agent。撤销 grant 后旧 citation 立即不可访问，内部 identity 不会进入模型结果。

## 生命周期命令

### 发现与构建

```bash
./scripts/muye.sh agent list
./scripts/muye.sh agent build product-handbook \
  --base-image 'python:3.11-slim@sha256:<64-hex-digest>'
```

`build` 要求根 `.venv`，按顺序运行 compileall、生成 Agent tests、Docker build 和 `docker image inspect`。BuildRecord
绑定 descriptor/source checksum、SDK、base image digest、本机内容寻址 image ID、SBOM 与测试报告引用。当前阶段的
`image_digest` 是本机 Docker daemon 的 `sha256:<image-id>`，不是 registry manifest digest。

### 同步与 CI

```bash
./scripts/muye.sh agent sync
./scripts/muye.sh agent sync --check
```

`sync` 支持零 Agent。未启用部署或缺少 BuildRecord 的合法 descriptor 只进入 report 的 `DISCOVERED` 状态，不进入
运行 Catalog/Compose；启用且证明完整的 Agent 以 `STARTING` 进入 candidate。

### 部署、下线与回滚

部署前需要 Docker daemon、Control、Main、active Resource Snapshot、目标用户 grant，以及根 `.env.example` 中的
Control/Main/Compose 配置：

```bash
./scripts/muye.sh agent deploy product-handbook --timeout 60
./scripts/muye.sh agent stop product-handbook --timeout 60
./scripts/muye.sh agent rollback product-handbook \
  --build-record build_20260731t010203z_0123456789ab --timeout 60
```

部署顺序为：重新 sync -> 确认本机 image ID -> Compose 启动 -> Control 全量 health/capabilities/identity 校验 ->
Main ETag reload 与 ACK -> 授权 Main smoke。ACK 超时时容器保持运行供诊断，Catalog 不会静默视为成功。

下线顺序为：提交移除目标的完整 candidate -> Main ACK -> Compose stop，避免 Main 继续选择已停止目标。回滚只接受
与当前 descriptor 和源码精确匹配的历史 BuildRecord，然后重放完整 deploy；源码已变化时必须重新构建，不能借回滚
绕过完整性检查。

## 健康、熔断与失败语义

Control 对 candidate 中每个 Agent 检查 `/health`、`/ready`、`/capabilities` 以及 agent/version/protocol、
descriptor/source checksum。全量通过并由 Main ACK 后才原子切换 active Catalog；candidate 或 Main 拒绝时保留旧版本。

后台 collector 只探测 `ACTIVE/DEGRADED` Agent，连续失败阈值触发 `ACTIVE -> DEGRADED`，连续成功阈值触发恢复。
状态变化会生成新的 checksum；Main 使用 ETag 原子替换 Registry，拉取或校验失败继续使用上一份有效 Catalog。

Main 为每个 `agent_id` 独立维护并发 semaphore 和 circuit breaker。目标失败不会熔断其他 Agent；请求取消会向当前目标
发送 `/cancel`，取消失败不吞掉上游取消。稳定错误投影为认证、授权、Catalog 拒绝、未就绪、依赖不可用或超时，不把
token、URL 细节或异常正文暴露给模型。

## 验证边界

常规 CI 覆盖零/多 Agent 的确定性生成、candidate 保旧、Main ACK、健康阈值、双用户授权工具投影、调用前复核、
服务身份、citation 撤权、Data Resource 授权、独立熔断、取消和生命周期命令顺序。真实 Docker build/deploy/rollback
依赖本机 daemon 与完整运行服务，不在常规无网络 CI 中执行；发布前必须在目标环境重放上述命令并保留输出记录。
